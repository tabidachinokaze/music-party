# 第 0 阶段验证记录

时间：2026-09-28，Linux x64 / Wayland。

后续用户实测修正：此版本创建的是双人一起听，目标实际为网易云官方多人房间。下列自动化与匿名音源验证仍有效，但**不能证明多人房间已实现**。开发验收以更新后的 `ROADMAP.md` 为准。

## 已通过

- `pnpm run check`：TypeScript 检查、15 项单元测试、Electron/React 生产构建。
- `pnpm test:desktop`：真实 Electron 窗口 + 本地模拟 API，覆盖扫码状态流转、建房、队列替换前确认、队列读取、结束前确认、诊断脱敏和 IPC 参数校验。测试不访问真实账号/房间。
- `pnpm run dist:linux`：生成约 143 MiB 的 AppImage；解包应用约 359 MiB，包含 API 模块及运行时依赖。
- 独立构建应用，未配置 `MUSIC_PARTY_API_URL`，隔离测试数据目录：取得真实登录二维码；查询歌曲 `1372188635`；实际音频 `paused=false`、`currentTime>0`、时长约 162.75 秒。验证时播放器静音，结束后关闭测试实例。
- 渲染层没有 Node `require`；登录凭据不出现在 IPC 返回与诊断记录中。
- Docker `moefurina/ncm-api:latest` 拉取检查：4.40.1，镜像未变化，没有重建现有容器。

## 已识别并处理

- 新版音源接口初始化 xeapi 密钥时报 `xeapi public key response missing sk`：调用同账号的普通 `/song/url` 获取音源作为回退，未启用第三方音源。
- 本机 Electron 的 Ozone headless 模式退出异常：桌面测试改用实际 Wayland 显示服务；应用保留默认沙箱设置。

## 待真实账号验证

## 0.4.0 成员修复与房间聊天（2026-09-28）

用户反馈 0.3.0 整体测试通过，进一步指出成员未显示并要求聊天。定位根因：官方 Android 模型 `LTMultiRoomInfo.roomUserList` 标有 `@JSONField(name=multiLtRoomUserAgg)`；此前实现和模拟数据均误用了内部属性名，导致真实成员丢失。现已修改实现与集成测试，使用实际 JSON 字段。同样识别 `multiRoomInfoDTO.chatRoomId` 供房间聊天使用。

56 项单测、类型检查和完整 Electron 回归通过。新增覆盖：官方成员字段与聊天室 ID、成员增减刷新、正文安全渲染、历史分页、官方聊天请求封装、服务端房间核对、重复发送去重、中文输入法 Enter 防误发、发送失败保留草稿、超时无自动重发、消息回显去重、可见性过滤及聊天正文不进入诊断。测试发消息仅使用本地模拟服务，没有向真实房间发送任何测试消息。

真实成员显示和与网易云官方 App 的聊天收发待用户验收。当前轮询读取聊天，并未实现云信 IM 实时推送。

0.4.0 独立构建已启动检查通过：窗口显示实际 0.4.0 版本，内置 API 模式可用，“房间聊天”侧栏正常打开；未加入房间时不能发送消息。AppImage 已生成，稳定路径 `dist/Music Party.AppImage` 指向本版本。
