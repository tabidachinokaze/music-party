# Music Party 单窗口界面规范

适用于 `redesign/adaptive-player` 的浏览页、正在播放页和两者共用的弹层。以下尺寸均为应用显示比例生效后的 CSS 像素。用户操作见[使用说明](ADAPTIVE-PLAYER.md)，组件所需字段和状态见 [UI 数据交接](ui-data/README.md)。

## 窗口与导航

| 可用宽度       | 浏览页                                                                                                                                                             | 正在播放页                                                         | 队列与房间聊天                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ------------------------------ |
| 小于 520 px    | 自定义标题栏左侧放返回和当前路径，右侧放「全部功能」，空间足够且有需要时显示全站搜索入口。有搜索框时放到单独的第二行并垂直居中。「全部功能」在空间不足时排成一列。 | 优先展示方形封面、歌曲信息、进度与播放控制。点「词」展开完整歌词。 | 共用底部面板，贴到播放栏上沿。 |
| 520 至 1039 px | 左侧导航只显示图标，悬停可见名称。                                                                                                                                 | 可用宽度至少 594 px 且高度至少 480 px 时，方形封面与歌词并排。     | 从右侧展开。                   |
| 1040 px 及以上 | 侧栏同时显示图标与文字，各功能使用各自入口，省去「全部功能」。                                                                                                     | 唱片与歌词并排。                                                   | 沿用同一右侧抽屉。             |

侧栏上方依次为音乐库、搜索、我喜欢的音乐、最近播放，下方为私信（信封图标）和设置。歌单、收藏专辑是音乐库的分类。浏览页标题、单个返回按钮和可点击的上级路径集中在顶部；内容区保留歌单名、会话联系人等当前对象的信息。鼠标侧键在浏览页、详情页和设置的访问记录中前进或后退。

正在播放页顶部仅保留「返回浏览」。标题栏的拖动区限于空白位置，按钮、头像、面包屑和搜索框必须能接收点击。右侧抽屉从窗顶延伸到播放栏上沿，盖住右上方窗口键；底部播放控制仍可用。窄窗的「全部功能」「添加到歌单」「切换歌曲」属于模态对话框，从窗口底边打开，可盖住播放栏。[窗口导航](../src/renderer/src/windows/AdaptiveShell.tsx) · [标题栏交互回归](../tests/desktop/titlebar.spec.ts)

## 播放栏、封面与歌词

- 浏览页的窄底栏左侧显示封面、歌名和署名，占满工具组以外的空间；播放键靠右，进度条横跨底栏上沿。竖屏正在播放页则让主播放键在上一首和下一首之间居中。
- 正在播放页的封面按可用宽度和扣除歌曲信息、控制区后的可用高度等比缩放。唱片、盘心和唱针一起缩放。歌词区随窗口增高展示更多上下文，自动跟随时当前行居中，手动翻阅后提供「回到当前歌词」。
- 播放栏左右工具组采用相同的组内间距。纯图标按钮共用点击区尺寸，极窄空间采用紧凑规格。计数角标附着在图标上，位数增加时相邻按钮保持原位。
- 在房间内，「一起听」在宽窗显示「N 人一起听」，收窄为耳机图标时用角标显示人数。图文按钮两侧留白相等。房间点赞与个人红心各有入口，点赞角标显示当前房间歌曲的总数，高亮取决于当前用户是否点过赞。[播放栏样式](../src/renderer/src/player/adaptive-transport.css)

## 列表、弹层与输入控件

| 组件           | 排版与操作                                                                                                                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 歌曲行         | 各行封面和歌名共用起始线。当前行的竖条、声波与封面垂直居中；列表容器宽度不超过 449 px 时收起序号列，竖条右缘到封面留 6 px。有有效 ID 的音乐人署名可分别跳转。当前歌曲属于列表且已滚出视口时显示定位按钮。                |
| 歌单与专辑卡片 | 歌单显示创建者和曲目数，省去逐卡的「自建／收藏」标签。专辑封面右侧为露出黑胶留出空间。                                                                                                                                   |
| 播放队列       | 队列名称放在页头。个人队列显示总曲数，模式与清空按钮在下一行垂直居中；序号列按队列最大位数统一留宽。房间队列用「正在听」「听过的」切换，重复推荐按各自的记录显示。                                                       |
| 抽屉与对话框   | 同类面板共用外沿、页头和导航。短表单随内容收高，长列表在正文内滚动，标题和主要操作仍可触达。大窗按功能给对话框留适当上限。滚动条浮在列表右侧留白内，显隐不挤动内容，也不压住行尾按钮。                                   |
| 添加到歌单     | 顶部放刷新、确认和关闭，下方固定目标歌曲与搜索框。仅歌单列表滚动。支持跨筛选多选，顶部显示确认数量。提交绑定打开时的歌曲，部分失败可单独重试。                                                                           |
| 按钮与输入     | 同组按钮的点击区、悬停底色、图标中心线一致。悬停提示说明当前动作，图标按钮提供可访问名称。搜索聚焦时高亮现有边框并显示清楚的光标。下拉菜单沿用应用主题并支持键盘操作；滑杆分别表现轨道、填充和滑块，键盘聚焦有可见反馈。 |

顶部搜索框的作用由页面决定。搜索页提交全站搜索，歌单或专辑详情筛选本列表的曲目，音乐库目录筛选歌单或专辑名称。设置项换行时，操作控件与图标右侧的标题和说明左对齐。[歌曲列表](../src/renderer/src/design/library-settings.css) · [队列](../src/renderer/src/player/QueueDrawer.tsx) · [添加到歌单](../src/renderer/src/AddToPlaylist.tsx)

## 私信、聊天与一起听

- **私信**在主界面打开。宽度足够时联系人与对话并排，窄窗逐级进入。联系人列表、会话页头与输入区平铺，以间距和分隔线组织。一条消息的文字、图片、邀请等共用一张消息卡；分别发送的消息各占一张。
- **快捷回复**由点击私信通知触发，并绑定该通知的联系人。已在私信页时点击通知直接定位到相应会话。房间聊天从播放栏的聊天按钮进入。
- **聊天工具**共用标题、工具区、可滚动内容区和按需出现的操作区。Unicode 表情放在 Emoji 面板，颜文字插入输入框，图片表情放在表情包面板。「最近使用」按账号本地保存。加载下一页时，保持面板高度、输入区位置和滚动位置稳定。
- **一起听**面板使用单行页头，返回、路径和关闭共用一行。房间人数在播放栏和房间信息中显示，待播数和同步按钮省去。后台同步在现有内容上更新，成员资料分批返回时用名单内占位，并在原位补齐。
- **房间主页与选歌**分为两种状态。入房前分别提供恢复、创建或匹配、通过邀请加入的入口。入房后依次显示在线成员、房间类型、创建者与音乐标签，两列文字字号和行高一致。点「切换歌曲」打开在线搜索；实心与空心红心只表示收藏状态，选歌返回原面板。匹配用歌的最近十条搜索与全站搜索分别保存。[房间面板](../src/renderer/src/windows/PanelPages.tsx) · [聊天输入组件](../src/renderer/src/ComposerPanel.tsx)

## 外观与壁纸

整个窗口共用一张壁纸和一个裁切焦点。布局、组件与弹窗分别叠加各自的底色；打开抽屉或切换页面时，背景中的同一处图案应当连续。默认使用主题底色，浅色主题以中性浅灰作为页面基底。

| 设置位置                  | 调整范围                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外观 → 编辑背景           | 选择本地图片，设置焦点、缩放、模糊与图片透明度。预览覆盖整个窗口，保存后应用，取消还原。                                                                            |
| 外观 → 界面透明度         | 分别调节布局、组件和弹窗的底色。窄窗底部面板与播放栏相接时，两者共用弹窗底色和透明度。                                                                              |
| 外观 → 显示大小、界面语言 | 显示大小同步缩放文字、图标、控件与间距，并按新的可用空间重排。界面语言可跟随系统或手动选择简体中文、繁體中文、English、日本語。歌曲、歌词、昵称与用户消息保留原文。 |

四项透明度在界面上都以 0% 表示不透明、100% 表示全透明。弹窗底色调到 100% 透明时，空白处直接透出原位置的页面内容和壁纸。调底色只作用于填充，文字、图标、封面和焦点指示保持清晰。自定义背景沿用组件库的字形与图标，无额外文字描边。[外观变量](../src/renderer/src/design/tokens.css) · [壁纸与弹层样式](../src/renderer/src/player-background.css)

核对布局时使用 321 × 682、740 × 590、900 × 722 和 1159 × 750 四个参考尺寸。对长歌名与多位数计数，复查 150% 显示比例下的四种语言；对弹层，分别在深浅主题及自定义壁纸下检查焦点、遮挡和滚动边界。[布局回归](../tests/desktop/layout.spec.ts) · [背景回归](../tests/desktop/background.spec.ts)

### 界面翻译

四种语言各有一份[语言文件](../src/shared/locales)。新增界面文案时，在四份文件里添加相同的键，调用方用 `t('settings.background.invalidFields')` 读取。动态值使用同名占位符，例如 `t('music.trackCount', { count })`。英文按数量选择 `one` 或 `other`，简中、繁中和日文可共用一种形式。系统提示通过键在展示时翻译，歌曲名、用户消息与发布说明按来源原文展示。

「跟随系统」按设备的首选语言顺序匹配。中文按文字和地区区分简繁体，找不到支持的语言时使用英文。手动选择会保存到下次启动。
