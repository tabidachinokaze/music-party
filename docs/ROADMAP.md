# 开发顺序

## 已确认的产品约束

- 核心目标为网易云**官方多人一起听**，至少三个账号同房，好友继续使用网易云官方 App。
- 私信/链接邀请指向同一个官方多人房间，不替换成 Music Party 自建房间。
- 桌面应用内置 API 和运行时，最终产物不要求用户安装 Docker 或 Node。
- 旧版双人接口验证不构成多人功能验收；此前按两人制定的标准已作废。

## 0. 官方多人协议核实（进行中）

已完成：客户端骨架、内置 API / Docker 两种调用方式、扫码登录、官方多人邀请解析、创建/加入/退出适配、多人快照播放器、成员列表、推歌与切歌请求、诊断导出、Linux 0.2.0 打包。

协议依据：官方分享页及其配置的 Android 体验包；具体端点、字段和单位见 `OFFICIAL-MULTIPLAYER.md`。旧双人接口已从客户端业务白名单和界面移除。

已自动验证：29 项单元测试与真实 Electron 三成员模拟流程，包括远端换歌跟随、进度对齐、推歌不抢播、本机暂停、拒绝旧邀请、权限错误、晚到响应隔离和退出。

已连接真实上游验证：匿名歌曲播放与官方多人邀请预览。用户已实测恢复房间、链接加入、音乐同步、推歌、请求下一首可用；仍待验证创建房间、明确三账号人数与不同角色权限；当前心跳轮询存在一个周期的延迟，后续接入云信 IM 推送。

退出门槛：至少三个账号（一个 Music Party、两个官方手机客户端）在同一官方多人房间中；桌面/手机两种发起方向均可加入；成员数、点歌和播放状态在实际支持的权限范围内一致；退出一个成员不会错误结束整个房间。具体上限与权限遵循官方协议，不预设可随意增加人数。

## 1. 基础音乐客户端（进行中）

0.3.0 已实现：创建/收藏歌单自动翻页，完整 trackIds 驱动歌曲分页与个人队列；喜欢列表与收藏切换；歌曲/歌单/歌手搜索及结果分页；搜索历史；自然结束自动切歌、循环模式、基础歌词、一次音源刷新及错误提示。等待真实音乐库实测。

退出门槛：独立日常播放可用，全部歌单加载完整，不把试听或不可播放歌曲当作正常完整音源。

## 2. 一起听核心（持续完善）

已具备独立 RoomPlayer、服务器快照版本校验、无回传循环、进度校准；0.5.0 增加断网和系统挂起时暂停并作废旧请求，在线/唤醒后先核对最新房间，再恢复心跳同步，保留用户本机暂停选择，不重放写操作。继续完善云信 IM、长期运行和真实断网/休眠验收。房间内点击歌曲统一推送到共同房间，音量仅影响本地。

退出门槛：至少三个账号连续播放、并发点歌、成员进出、短暂断网和后台运行后都能收敛到正确状态，并与官方 App 的行为一致。

## 房间成员与聊天（0.4.0 已实现，待跨端实测）

修复官方 JSON 字段映射，成员 10 秒刷新；独立房间文字聊天、历史分页、未读提示、发送目标核对、正文诊断脱敏、重复请求去重和失败保留草稿。打开聊天 3 秒轮询，收起 8 秒轮询；云信即时推送后续接入。该功能属于官方多人房间内聊天，不替代私信模块。

## 3. 私信邀请闭环（0.5.1 已通过用户邀请验收）

会话/历史分页、未读数量、联系人筛选、关注列表选人、文字私信；从文字/结构化消息中提取经过严格验证的官方多人 URL 或已核实深链，预览后加入，切换房间前确认并重新检查邀请。分享当前房间先确认收件人，服务侧核对房间和发送者；保留失败草稿，发送结果未知时不自动重发，重复 requestId 在进程内去重。账号变化作废旧请求，诊断仅保留消息数量等元数据。

模拟测试覆盖完整流程。0.5.1 修复原生邀请卡片的 nativeUrl/url1/url2 编码后，用户明确反馈私信邀请验证通过。更多非邀请消息类型和实时通知仍待完善。

## 4. 桌面打磨（0.6.0 Linux 已实现）

托盘菜单和后台播放、单实例显示已有窗口、标准 Media Session 系统播放信息与媒体控制、深色/浅色/系统主题、音量/个人循环模式/窗口位置持久化、应用及托盘图标、Linux desktopName 配置。退出应用会有限等待离开房间；关闭到托盘保留会话。

75 项单测与三项 Electron 回归通过。自动检查覆盖隐藏窗口继续播放、菜单控歌、系统歌曲元数据、个人/多人控制边界、重启恢复设置、重复启动显示已有窗口和关闭退出。实际键盘媒体键、不同桌面环境长时间后台运行仍需用户验收。

后续：云信 IM 即时推送与长时间稳定性、Windows/macOS 构建验收、发布签名与自动更新。
