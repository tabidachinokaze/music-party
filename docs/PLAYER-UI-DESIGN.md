# 历史设计稿 · 9:16 主窗与外挂窗口

初版希望只开一扇小窗就能听歌，需要读词或回私信时再利用桌面或副屏的空位。试用后，歌词、私信和队列分布在多扇窗口，查找和切换过于分散。后续设计保留了竖屏封面和常驻进度条，改由同一窗口随尺寸容纳更多内容。当前布局与交互见[单窗口界面规范](UI-GUIDELINES.md)，页面所需数据见 [UI 数据交接](ui-data/README.md)。

## 初版如何使用桌面空间

- **主窗。** 以 360 × 640 为标准稿，放一张 328 × 328 的方形封面。下方常驻进度、两端时间和播放键，第二排提供喜欢、添加到歌单、播放调节和窗口目录。初次启动只开主窗。
- **外挂。** 歌词窗优先贴在主窗左侧，私信和通知靠右。用户可以把任一扇拖到副屏。打开、关闭或调整外挂时，主窗保持原有大小与比例。
- **贴靠手势。** 原型建议在两窗边缘相距约 16 px 时提示贴靠，松手后留 8 px 间隙。拖动主窗会带着贴靠的窗口移动；向外拖开约 24 px 即解除跟随。最小化和还原只联动仍贴靠的窗口。
