# Music Party

[GitHub 项目](https://github.com/tabidachinokaze/music-party) · [下载安装包](https://github.com/tabidachinokaze/music-party/releases) · [反馈问题](https://github.com/tabidachinokaze/music-party/issues)

网易云音乐**官方多人一起听**桌面客户端。好友继续使用网易云官方 App；桌面端复用网易云的房间、成员、队列与播放状态。

当前版本 **0.7.0：首个公开试用版**。0.1.0 误用了双人接口，已替换。多人接口已根据官方分享页与其链接的 Android 客户端核实并接入；用户已实测恢复房间、链接加入、音乐同步、推歌、请求下一首可用；创建房间和不同人数/权限组合继续验收。

## 桌面产物

Linux x64：`dist/music-party-0.7.0-linux-x86_64.AppImage`，也可运行 `dist/linux-unpacked/music-party`。

应用包含 Electron、前端和 `api-enhanced`，无需 Docker、Node 或相邻源码仓库。API 在独立 utility process 中运行，不监听 HTTP 端口。GitHub Release 工作流同时构建 Linux x64 AppImage 和 Windows x64 NSIS 安装包。macOS 尚未提供签名和验收版本。

## 本轮实现

0.7.0 接入 GitHub Releases 应用内更新，在“设置 → 应用更新”检查、下载，再确认安装并重启。默认不会自动下载或自动安装，也不会因为正常退出就安装已下载更新。0.6.x 及更早版本需手动安装一次 0.7.0，之后可在应用内更新。发布方法见 [发布文档](docs/RELEASING.md)。

0.6.0 增加系统托盘、后台播放、重复启动时显示已有窗口、系统 Media Session 歌曲信息与播放控制、深色/浅色/跟随系统主题、音量/循环模式/窗口位置保存，以及应用和托盘图标。默认关闭窗口隐藏到托盘，真正退出请使用托盘菜单、设置页的“退出 Music Party”或 Ctrl/Cmd+Q。

0.5.1 补齐官方私信邀请卡片的跳转解析：解开 `nativeUrl` 中的 `url1`（原生入口）、`url2`（网页后备地址）及 WebView `url` 的百分号编码；同一房间去重。保留手机分享的说明文字，同时显示多人邀请卡片。解析只提取并验证官方多人入口，不执行外层 URI。

0.5.0 新增网易云私信会话/历史分页、未读数量、关注联系人选择、文字私信、官方多人邀请识别与分享。发送邀请前显示收件人及链接；服务侧确认当前账号仍在该房间，且只向一个收件人发送。恢复网络或系统唤醒后重新读取房间状态，不重放推歌/发消息等写操作。

0.4.0 修复真实房间成员解析：读取官方字段 `multiLtRoomUserAgg`，每 10 秒独立刷新，也支持手动刷新；某位成员字段异常不会中断歌曲播放。新增官方房间文字聊天、历史分页、未读提示、发送状态与失败保留草稿。聊天在打开时约每 3 秒刷新、收起时约每 8 秒刷新，尚非云信实时推送。

0.3.0 修复未选歌时以 `songId=0` 创建房间：先播放一首可完整收听的歌曲，开房按钮才可用；官方歌曲资格拒绝会显示中文说明。另新增完整歌单列表、我喜欢的音乐、歌曲/歌单/歌手搜索、搜索历史、基础滚动歌词、个人队列与顺序/列表循环/单曲循环。

0.2.1 兼容从 Markdown 复制的 `\&`、`&amp;` 等链接分隔符；窗口标题和侧栏显示实际安装包完整版本号。恢复房间已增加队列与播放进度的桌面回归验证；未取得快照时显示加载状态，不显示误导性的零首。

- 扫码登录，支持系统密钥环保存凭据；密钥环不可用时仅保持本次会话。
- 官方多人链接识别（`multishare/index.html`、`inviterUid`、`isFLT=false`）；拒绝误用双人或“跟听”链接。
- 多人邀请预览、创建好友多人房间、确认加入、恢复当前房间、复制多人邀请、离开房间。
- 在线人数、成员列表、当前歌曲和接下来歌曲 ID 展示。
- 搜索与本地播放；在房间内点击歌曲的 `+` 按钮或双击歌曲，使用官方推歌操作加入共同队列。
- 跟随心跳快照加载当前歌曲、对齐进度、拒绝旧版本状态，退出后丢弃未完成的音源请求。
- 暂停仅影响本机；恢复时对齐房间。多人房间不支持本地拖动服务端进度。
- “请求下一首”提交官方切歌操作，权限不足或频率受限时显示真实错误。
- 最近 300 次脱敏诊断和导出。诊断仍保留用户/房间/歌曲 ID。

## 实测步骤

1. 打开 **0.7.0**，扫码登录。
2. 若账号已经在官方多人房间中，点击“恢复当前房间”；否则粘贴官方多人链接，点击“预览邀请”检查，再“加入房间”。
3. 准备另外两个账号，在官方 App 加入同一房间，确认桌面显示至少三人。
4. 在桌面搜索歌曲并推送，确认官方 App 的队列变化；在手机切歌，确认桌面随后跟随并对齐进度。
5. 验证本机暂停不会暂停房间，恢复同听后回到房间进度；验证离开一个成员时其他成员仍在。
6. 先在本机播放一首歌曲，再点击“创建多人一起听”，复制链接供官方 App 加入。未选歌时不能开房；歌曲不符合官方要求时请换歌。
7. 如失败，在“观测记录”导出诊断，记录触发动作及 App 版本。无需提供账号 Cookie。

当前同步使用心跳轮询，按服务端 `heartBeatDuration`（秒）调度。官方客户端还使用云信 IM 推送，本版本尚未接入，因此手机操作到桌面跟随可能存在一个心跳周期的延迟。完整多账号权限验收、低延迟 IM 推送、其他操作系统打包和正式发布配置仍在后续开发中。

## 桌面功能与设置

- 默认点窗口关闭按钮后隐藏到托盘，播放器、房间心跳、聊天和私信连接继续运行。从托盘可显示窗口、暂停/恢复、上一首/下一首、打开歌词/设置和退出；托盘不可用时关闭窗口会退出。
- 在“设置”里可关闭后台运行，选择深色、浅色或跟随系统，调整音量和个人队列循环模式。主题、音量、模式以及窗口大小/位置写入应用数据目录的 `settings.json`，凭据仍单独加密保存。
- 重复打开同一用户数据目录的 0.6.0 实例会显示已有窗口，避免多个播放器并行运行。更新前请关闭旧版本，0.5.x 不具备此单实例逻辑。
- 通过标准 Media Session 向系统提供歌曲、歌手、专辑、封面、播放状态和进度；系统媒体键/控制面板可执行播放、暂停、切歌。支持情况依赖桌面环境，未抢占全局媒体键。
- 多人房间中暂停只影响本机，下一首请求官方房间切歌；上一首与进度跳转不会发出无效房间指令。
- 真正退出时会尝试离开当前官方多人房间，最多等待 3 秒后关闭应用。关闭到托盘不会离开房间。退出不会自动发送私信或草稿。
- 空格在非输入区域切换播放；Ctrl/Cmd+F 打开搜索；Ctrl/Cmd+, 打开设置；Ctrl/Cmd+Q 退出。

Linux x64 AppImage 已构建并测试；Windows x64 由 Release 工作流构建。试用版尚未代码签名，Windows 可能出现未知发布者提示；macOS 暂未开放自动安装更新。

## 房间成员与聊天

进入官方多人房间后，房间卡片显示头像、昵称和在线人数，点击“刷新成员”可立即更新。服务端若只提供部分成员，显示已取得的成员数量。

点击侧栏“房间聊天”或房间卡片“打开聊天”查看聊天，支持加载更早记录。输入文字后点击“发送”或按 Enter，Shift+Enter 换行；支持中文输入法，最多 100 个 UTF-16 字符单位（与官方客户端输入限制一致）。普通文本和 emoji 可以发送；贴纸等其他类型暂用文本占位展示。

发送目标由账号当前官方房间快照中的聊天室 ID 决定，不能手工指定其他聊天室。成功提交后等待房间记录回显，不把 HTTP 失败显示为发送成功。超时不自动重发，先刷新记录确认后再手动重发；关闭聊天保留草稿，离开/切换房间会清空该会话。聊天正文不会进入诊断导出。

房间聊天与网易云私信使用不同入口：侧栏“房间聊天”是当前多人房间内的消息；“私信”是网易云账号的联系人会话。

## 私信与邀请

侧栏“私信”提供会话列表、筛选、历史消息及分页。可以点击 `+` 从“我关注的人”选择收件人，或输入网易云用户 ID 打开会话。普通私信最多 500 个 UTF-16 字符单位；发送失败保留草稿，发送结果不明确时先刷新确认，不会自动重发。切换联系人保留各自的未发送草稿，退出账号清空私信与草稿。

收到含官方 `multishare` 链接的文字或 JSON 消息时，会显示邀请卡片；也识别已核实的 `orpheus://nm/multiListenTogether/joinRoom` 深链。先“检查邀请”，确认可用后“加入一起听”。已在其他房间时需要确认切换；实际离开前会再次检查邀请有效性。未知消息类型使用文字占位，不因无法识别而破坏整段会话。

在房间卡片点“私信邀请”，或在联系人会话点“邀请到当前房间”，确认收件人和链接后发送普通文字＋官方多人链接。当前不伪造网易云原生邀请卡片，不根据任意 roomId 属性猜测消息类型。

私信会话列表在页面打开时约 15 秒刷新，后台约 60 秒；已打开的会话约 5 秒读取新消息。私信正文和结构化消息内容不进入诊断导出。当前基于轮询，尚未接入网易云实时通知通道。

## 音乐库与个人播放

登录后自动读取创建和收藏的全部歌单；有更多页时继续读取，异常不会误报“全部”。歌单歌曲从完整 trackIds 分批读取，每批 100 首；“播放全部”使用完整 ID 队列，后续歌曲播放时再获取音源。喜欢/取消喜欢等待接口成功后在各页面更新。

歌曲在个人模式下进入个人队列，支持上一首、下一首、自然结束自动播放下一首和循环模式；进入房间时保留个人队列，离开后保持暂停。房间模式下歌曲行操作改为推歌，不覆盖整个房间队列。音源加载失败时会尝试刷新一次，权限不足/仅试听不会冒充完整播放。

“歌词”跟随当前播放歌曲和进度。“搜索”支持歌曲、歌单、歌手与结果分页；搜索历史仅保存在本机。

## 开发

需要 Node 24 和 pnpm 11.26.0。网易云 API 使用固定 npm 依赖 `@neteasecloudmusicapienhanced/api@4.40.1`，已把此前本地验证版本的 NMTID 修复保存在 `patches/`；无需相邻源码仓库。

```sh
pnpm install --frozen-lockfile
pnpm dev                 # 内置 API
pnpm dev:docker          # 复用 http://127.0.0.1:3000
pnpm run check           # 类型、单元测试、构建
pnpm test:desktop        # 真实 Electron + 模拟官方多人响应；需要桌面显示服务
pnpm run pack            # 独立应用目录
pnpm run dist:linux       # AppImage + 更新描述文件
pnpm run dist:win         # 在 Windows 上生成 NSIS + 更新描述文件
```

`MUSIC_PARTY_API_URL` 覆盖开发 API 地址，默认内置。Docker 模式通过现有 `/api` 通用接口转发**固定白名单**中的多人路径，不需要修改 Docker 镜像。所有 HTTP 调用避免复用上游按 URL 缓存的 POST 响应；renderer 不能任意指定路径、Cookie、代理或校验令牌。

`MUSIC_PARTY_PROFILE` 可指定测试数据目录。Electron 二进制首次使用时下载，可预先执行 `pnpm exec install-electron`。客户端使用 API 包的 `main.js` 模块入口，所有依赖由 lockfile 固定。
